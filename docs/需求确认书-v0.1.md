## 0. 一句话结论

本轮交付一个 **可跑通端到端的工程骨架**：目录、模块、数据模型、接口契约、配置体系、mock 数据源、Docker/compose、Vue 只读控制台、测试与验收脚本全部到位，整条链路（采集→检测→编排→脱敏→诊断→告警→确认→入库→RAG 命中）可在本地一条命令跑通；其中 Agent 推理与检测算法先以**规则桩**实现，接口与降级路径留好，后续填充真实 LLM 推理与算法而不返工。

## 3. 关键契约（骨架阶段即冻结）

### 3.1 事件与诊断

```
AnomalyEvent : id, source(metric|log|trace|k8s), cluster, namespace, target,
               metric, window(start,end), severity, value, threshold, rule_id, created_at
DiagnosisFragment : agent(metric|log|trace|root_cause), confidence(0~1),
                    evidence[], conclusion, degraded(bool), skip_reason
DiagnosisReport : id, anomaly_id, status(ok|partial|failed), root_cause,
                  confidence, fragments[], suggestion[], rag_hits[], markdown, created_at
```

### 3.2 告警与经验

沿用开发文档 5.1 / 5.2，补充三个字段：
- `Alert.degraded: bool` — 诊断是否降级产出
- `Alert.group_key: str` — 聚合键（cluster+namespace+target+metric）
- `Experience.embedding_source: str` — 记录 embedding 供应商与模型，便于以后换模型时重建

### 3.3 配置项（环境变量）

`PROMETHEUS_URL` / `ELASTICSEARCH_URL` / `JAEGER_URL` / `KUBERNETES_API_URL` /
`LLM_API_KEY` / `LLM_BASE_URL` / `LOCAL_MODEL_URL` /
`EMBEDDING_BASE_URL` / `EMBEDDING_MODEL` / `EMBEDDING_API_KEY` /
`KNOWLEDGE_BACKEND(chroma|faiss)` / `DATA_DIR` / `MOCK_MODE(true|false)` /
`ENABLE_TRACE_AGENT` / `ENABLE_K8S_ADAPTER` / `DETECT_INTERVAL` / `RETENTION_DAYS` /
`AUTH_TOKEN` / `ALERT_COOLDOWN` / `ALERT_GROUP_WINDOW`

## 4. 规则与例外

| 场景 | 规则 |
| --- | --- |
| 某维度 Agent 超时/失败 | 该维度标 `degraded`，根因置信度按缺失维度加权下调，报告明示缺口 |
| LLM Key 未配置/失效 | 自动切规则桩输出保守结论，告警照常发出，报告标注「未使用 LLM」 |
| 脱敏规则加载失败/正则异常 | fail-closed：外发请求直接拒绝，写审计 + 触发自身 P1 告警 |
| 脱敏后仍疑似含敏感串 | 二次校验（正则扫描）命中即拦截，同 fail-closed 路径 |
| 数据源未配置 | 该适配器跳过，启动日志明示，不影响其他链路 |
| 数据源不可达 | 采集重试 3 次（指数退避）后跳过本轮，记录来源健康度 |
| 告警风暴 | 5 分钟窗口按 `group_key` 聚合，首次发全文、后续发计数摘要；P0 例外不抑制 |
| 经验重复 | 入库前相似度 > 0.92 判重复，返回合并提示而不写入 |
| 经验回滚 | 状态置 `rolled_back`，从检索索引移除，保留审计与原始向量 |
| 时区 | 存储 UTC，展示与报告按 Asia/Shanghai 渲染 |

## 5. 验收清单（脚本自证）

| # | 验收项（对应需求文档第 6 章） | 判定方式 |
| --- | --- | --- |
