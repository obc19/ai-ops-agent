## 2. v0.2 新增能力验收（手工脚本验证）

| 能力 | 验证方式 | 结果 |
| --- | --- | --- |
| 告警状态机 | 检测 → 通知 → 确认 → 关闭 → 复发热重开 | **PASS**：`triggered → notified → confirmed → resolved → triggered`，`status_history` 完整记录 actor 与备注 |
| 非法流转拦截 | 在 `confirmed` 状态下调用 `reopen` | **PASS**：HTTP 409「不允许从 confirmed 流转到 triggered」 |
| 三角色鉴权 | 不带头 / viewer / operator / 错误 token 分别访问读写接口 | **PASS**：无 token 401、viewer 读 200、viewer 写 403、operator 写 200、错误 token 401 |
| 本地体验模式 | 三个 Token 全空时访问全部接口 | **PASS**：全放行，`/healthz` 始终开放 |
| 多集群 | `CLUSTERS_CONFIG` 配置 prod + staging，查看采集器实例 | **PASS**：`prometheus@prod`、`elasticsearch@prod`、`prometheus@staging` 三实例，`/clusters/sources` 正确回显 |
| Alertmanager 接入 | 提交含 firing + resolved 两条告警的 v4 payload | **PASS**：接收 1 条、跳过 1 条；事件映射为 P0，集群/命名空间/对象取自 labels，四渠道通知成功 |
| 脱敏 fail-closed | 人为清空脱敏规则后触发外发 | **PASS**：`EgressBlocked` 抛出、审计写 `llm_egress_blocked`、生成 `system/ai-ops-agent/desensitizer_error` P1 告警 |
| 飞书 / 钉钉加签 | 配置密钥后检查请求体/URL | **PASS**：飞书 body 含 `timestamp`+`sign`；钉钉 URL 含 13 位 `timestamp`+`sign`，HMAC 结果与官方算法一致 |
| CLI 新命令 | `clusters` / `ingest` / `alert-reopen` | **PASS**：`ingest` 输出告警 ID 与状态 `notified`，`alerts --status notified` 可筛出 |
| 回归测试 | `pytest -q` | **PASS**：25 项全部通过（未新增测试） |

## 5. 复现方式

```bash
# 1) 端到端验收（含 8 条需求标准，自动跳过无 Docker 项）
python scripts/demo.py

# 2) 手工起服务
MOCK_MODE=true python -m uvicorn app.main:app --host 127.0.0.1 --port 8080

# 3) 状态机与接入
curl -X POST localhost:8080/_mock/fault -H 'Content-Type: application/json' \
     -d '{"target":"order-service","metric":"cpu_usage_percent"}'
curl -X POST localhost:8080/api/v1/diagnostics/detect -H 'Content-Type: application/json' -d '{"notify":true}'

# 4) 集群与接入 CLI
python -m app.cli.ops_cli clusters
python -m app.cli.ops_cli ingest --target payment-service --metric HighLatency --severity P0
```
